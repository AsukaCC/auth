# 功能核查与后续范围

核查对象是当前 Go / React / SQLite 实现。系统已具备内部身份中心的核心闭环，但不是完整的 IAM / CIAM 产品，以下范围需要根据业务再推进。

| 范围 | 当前结论 | 证据 / 后续 |
| --- | --- | --- |
| 管理员初始化、角色与应用归属 | 已实现 | `bootstrap_test.go`、`auth_test.go`；禁止公开初始化和第三方提权 |
| 控制台 / 第三方会话、撤销与过期 | 已实现 | Cookie / Bearer 分离，已有会话与凭据行为测试 |
| 密码、2FA、防重放、找回申诉 | 已实现 | bcrypt、AES-GCM、一次性备用码 / 恢复 Token、管理员核实流程 |
| 用户基础资料 | 本次补充 | 本人资料编辑，管理员只读查看，版本冲突检测；电话和组织为自述 |
| 用户画像 | 本次补充 | 管理员内部标签 / 备注 + 用户活跃与应用使用历史；不以自述字段授予权限 |
| 管理员用户可视化 | 本次补充 | 总量、在线、DAU / 7 日 / 30 日活跃、30 日趋势、角色和安全分布、用户详情 |
| 用户目录 | 本次补充 | 服务端分页、角色 / 状态筛选、姓名 / 邮箱 / 组织 / 部门 / 标签搜索；保留旧列表 API 兼容 |
| 统计准确性 | 有明确边界 | UTC 日、心跳口径、历史回填范围详见 `architecture.md`；不是停留时长统计 |
| 邮箱变更与验证、手机号验证 | 未实现 | 需要独立验证凭据、过期、防重放、会话撤销规则；不能复用资料编辑绕过 |
| 应用成员、租户隔离 | 未实现 | 当前用户是全局目录，Key scope 约束接口，不是应用成员白名单 |
| OAuth / OIDC、SSO、SAML、SCIM | 未实现 | 当前是专有服务端 API；不能对外宣称标准协议兼容 |
| WebAuthn / Passkeys、风险控制 | 未实现 | 当前为密码 + TOTP，未提供设备信任或自适应认证 |
| 失败登录分析与防撞库 | 部分 | 已有 IP 限流；未持久化完整失败登录事件，未实现共享限流 / 账户维度风控 |
| 资料导出 / 删除与数据保留 | 未实现 | 需要明确合规和保留政策后设计；不擅自删除审计或用户数据 |
| 应用编辑 / 删除、Key 自动轮换 | 未实现 | 当前应用创建、Key 签发 / 撤销可用；删除需定义历史审计和关联数据语义 |
| 多实例 / 多集群 | 设计已梳理，运行时未实现 | 当前强制 SQLite 单实例；详见 `architecture.md` 的分阶段迁移与验收 |
| 监控、告警、无停机发布 | 部分 | 已有公开数据库健康检查；发布仍停服备份，不提供全链路可观测性 |

## 优先顺序

1. 根据真实使用规模，确定邮箱验证、应用成员边界、共享限流的优先级。若服务公网用户，应先完成账户验证与防滥用设计，再扩充更多画像字段。
2. 明确资料和活跃历史的保留周期、管理员访问制度；再增加定时归档、导出和删除流程。
3. 出现单实例容量或可用性要求后，按架构文档迁移 PostgreSQL + 共享限流，完成跨副本安全验收，再部署多个 Auth 副本。
4. 多地域优先灾备和单写切换；跨地域多写、标准身份协议和租户隔离均作为独立功能设计、评审和测试。

不要将“新增了用户分析页面”解读为以上所有缺失的 IAM 功能已经实现。真实 SMTP 送达、外部网关、真实生产负载和多地域故障转移均需要对应环境验证。
