新增 Google、GitHub 第三方登录、已注册账户绑定/解绑，以及业务应用的 OAuth 授权码交换 API。

- 管理员可在「第三方登录」配置 Client ID、Client Secret 和注册开关；Secret 加密保存、不返回明文。
- 已有账户在「账户安全」重新验证密码及已启用的 2FA 后绑定/解绑。同邮箱不会自动合并账户，第三方登录继续校验本地 2FA。
- 支持一次性 state、S256 PKCE、浏览器绑定、授权码防重放和应用隔离。新身份注册默认关闭，开放后仅创建普通用户并要求设置本地密码。
- 应用管理新增精确回调地址配置；新增 `/v1/auth/oauth/{provider}/start` 和 `/v1/auth/oauth/exchange`，交换结果沿用现有应用 Bearer 会话。
- 同步更新网页接入文档、README 和完整的 [OAuth 配置/API 文档](https://github.com/AsukaCC/auth/blob/v1.3.0/docs/oauth.md)，包含 Google/GitHub 后台配置和 Node.js PKCE 示例。

### 从旧版升级

本版本数据库结构从 **2 升级至 3**，也支持结构 1 直接迁移；保留已有用户、密码、2FA、会话、资料、统计及主密钥。升级前自动停服备份，迁移后禁止回退结构 1/2 镜像；跨结构健康检查失败只允许向前恢复兼容镜像。

**旧版部署代理仅支持结构 1/2，首次升级 1.3.0 必须使用完整新安装包在原服务器安装目录升级工具与代理。** 保留 `.env`、`.deployment/`、备份和原数据卷，不要新建数据卷或覆盖数据库。

```sh
sudo env AUTH_ALLOW_SCHEMA_UPGRADE=true ./authctl.sh update
# 原源码部署首次接管使用：
sudo env AUTH_ALLOW_SCHEMA_UPGRADE=true ./authctl.sh adopt
```

升级后的兼容版本继续支持管理员网页更新。Google/GitHub 登录需在各服务商创建 OAuth 应用，在后台填写实际 Client ID、Client Secret，并精确登记页面显示的回调地址。
